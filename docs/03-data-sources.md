# Stage 2.5 · 多载体「识别 → 导出 → 归一」矩阵（Issue #100 / Epic #74）

> 目的：把家庭机器上可能留下 AI 痕迹的**所有载体**先列全，逐个讲清三件事——
> **识别**（本机/网页里长什么样、放在哪）、**导出**（能不能拿到带原文和时间的原件，拿不到就明确标注不可导出）、
> **归一**（拿到后转成 Stage 3.1 白名单格式再进 `raw/`）。
> 浏览器扩展怎么装、开关怎么开，见 [02-multi-platform-export.md](02-multi-platform-export.md)；本表只负责"哪些载体、各归到哪、哪些根本进不了库"。

---

## 一、白名单边界（先记死）

Stage 3.1 只解析这四种扩展名（与 `scripts/01_clean_and_index.py` 的 `RECOGNIZED_EXTS` 对齐）：

| 白名单扩展名 | 01 内解析入口 |
|---|---|
| `.json` | `_extract_from_json`（映射树 / 会话列表 / 单条消息对象） |
| `.jsonl` | `_extract_from_jsonl`（每行一个消息对象） |
| `.md` | `_extract_from_text`（AfterChat 真实导出格式 / 旧版 User: Assistant: 格式） |
| `.txt` | `_extract_from_text` |

**白名单外的文件**（`.sqlite`/`.db`/`.zip`/`.png`/`.jpg` 等）：01 扫描时会计入 `skipped_unrecognized_files` 并在明细里列出文件名与扩展名，**不再静默跳过，也不会被解析成记录**。它们必须在上游先归一成白名单格式；归一没成功的，在个人档案里标注"未入库"，不要假设已经覆盖。

| # | 载体 | 识别特征（本机位置 / 扩展名） | 可导出性 | 归一动作（进 `raw/` 前） | 证据级别 |
|---|---|---|---|---|---|
| 1 | 本地 CLI / 编码助手会话 | `~/.claude/projects/**/*.jsonl` 等 CLI 会话归档 | **可导出**：会话本身就是本地文件，只读复制即可 | `.jsonl` 直接进 `raw/local/`，01 按 jsonl 解析 | 本机首次扫描实测（Gate0 g2，ISSUE-006～010）：`.claude/projects` 下 33 个 `.jsonl`、约 16MB |

| 4 | 图片 / 截图 / 剪贴板图 | `.png`/`.jpg`/`.jpeg`/`.webp`，聊天截图、界面截图 | **管线内不可导出为文本**：本仓库无 OCR 环节 | 人工抄录或外部 OCR 转写成 `.md`/`.txt`，注明截图原始日期与出处，再进 `raw/notes/`；转写不得改原话 | 边界项：OCR 不在当前管线，截图类一律按"待人工转写"处理 |
| 5 | 网页登录态会话（网页版，仅登录态） | DeepSeek 网页版、腾讯元宝网页版等：本机**没有落地文件**，内容只在浏览器登录态里 | **有登录态才可导出**：按 02 指南在已登录的日常浏览器里用扩展逐条/批量导出；**无登录态 = 不可导出**，不得凭印象补写 | 导出的 `.md`/`.json` 进 `raw/web/`；导不出的平台在档案标注"仅登录态、本次未导出" | 本机实测线索：网页版只有登录态（ISSUE-023）；导出结果以真人在场操作为准 |
| 6 | 笔记 / 碎片记录 / 语音转写 | flomo、本地笔记、语音备忘录导出的 `.md`/`.txt` | **可导出**：客户端导出纯文本 | 直接进 `raw/notes/`；保留"当时口述"与"事后追忆"的时间差，不得抹平 | 02 指南第二节已述 |
| 7 | 其他本地 JSON 归档 | `.openclaw/` 等目录下的 `.json` | **可导出**：本地文件 | `.json` 直接复制进 `raw/`；嵌套结构由 `_records_from_json_obj` 摊平 | 目录存在为本机实测；嵌套形态未逐一核对，标 UNVERIFIED |

## 三、各载体的具体处置

### 1. 本地 CLI 会话（`.jsonl`）

- **识别**：编码助手 / CLI 把每轮对话写成一行 JSON，落在家目录隐藏目录下的项目子目录中。
- **导出**：只读复制，不要移动或改动原库；复制前先确认不是正在写入的临时文件。
- **归一**：`.jsonl` 已在白名单，无需转换；若 CLI 导出的是单个大 `.json` 会话列表，归入第 7 类走 json 解析。

### 2. 桌面客户端数据库（`.sqlite`/`.db`）

- **识别**：桌面客户端把会话存在本地数据库文件里，目录名随客户端而异。
- **导出顺序**：先找客户端自带的"导出对话 / 备份"入口；没有入口时，再考虑只读方式导出。**禁止直接把 `.db` 复制进 `raw/` 指望 01 读出**——它在白名单外，只会被计入 skipped 列表。
- **未覆盖**：各客户端库的表结构、消息字段、时间字段命名未逐库核对；拿到库后需先只读看一眼 schema，再写对应导出脚本，不要假设字段和第 1 类 `.jsonl` 一致。

### 3. 批量压缩包（`.zip`）

- **识别**：从对话列表页触发批量导出得到的归档；02 指南 0.2 节。
- **归一**：解压后只取内部 `.md`/`.json` 原件；压缩包、解压出的临时目录不进 `raw/`。
- **已知风险**：批量进度曾出现 `331 → 56/331` 回退循环（Issue #7），归档是否完整要核对解压出的会话数量与列表数。

### 4. 图片 / 截图

- **识别**：聊天里发过的界面截图、手写备忘拍照。
- **边界**：本管线不做图像识别。截图里的内容必须转写成文本才能入库；转写件要标注"来自截图转写"，日期用截图对应的事发日期，不用转写当天日期。

### 5. 网页版登录态会话

- **识别**：本机磁盘上找不到对应文件，会话只存在于浏览器登录后的网页里。
- **导出前提**：必须在平时已经登录该平台的浏览器里操作；客户端内置浏览器通常不复用登录态（见 02 指南 0.4 节）。
- **不可导出标注**：某平台本次无法登录、或扩展抓不到内容时，在档案对应条目写"未导出（原因：登录态不可用 / 平台无出口）"，不要让 AI 凭印象补对话内容。

### 6. 笔记与语音备忘

- 已是 `.md`/`.txt` 的碎片记录直接入库；语音转写文本要保留原始口语，整理稿与口述原稿分开存。

### 7. 其他本地 JSON

- 单条消息对象、会话列表、嵌套 `parts` 结构都由 01 的 json/jsonl 入口摊平；解析不出记录时先检查 JSON 是否损坏，而不是改原文。

## 四、入库前自检（对照 01 输出）

跑完 `01_clean_and_index.py` 后看统计：

- `total_raw` / `indexed`：实际进冷库的记录数；
- `skipped_unrecognized_files` + `skipped_unrecognized_detail`：白名单外被挡下的文件清单。**这组数大于 0 不是错误，但要逐条回到上表决定：是归一后重跑，还是在档案里标"未入库"。**
- 不要把 `indexed=0` 或 skipped 一堆当成成功；见 01 脚本的 `INDEX_EMPTY` / `WARN` 提示。

---

## 五、证据分级与未覆盖边界

- **本机实测**：`.claude/projects` 下 `.jsonl` 数量与体积；各客户端目录是否存在；网页版仅有登录态（Gate0 g2 / g3 取证记录，ISSUE-006～010、ISSUE-023）。
- **UNVERIFIED（待真人真实机器复核）**：第 2、7 类库表结构与字段命名；各客户端导出入口是否真实存在；批量 zip 的完整性闭环。
- **本管线不覆盖**：图片 OCR；`.sqlite`/`.db` 直接解析；登录态代登录；任何脱离原件的 AI 回忆补录。
- 本表只回答"载体归到哪"，不替代 02 指南的扩展安装与开关自检步骤。
