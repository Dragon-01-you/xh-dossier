# ADR-0002: 访谈答案优先于 raw 回填，冲突显式标 `[待确认]`

- **Status**: Accepted（E3-T2 / issue #89）
- **Date**: 2026-11-23

## Context

基线 build 链路只有 raw → index → match → bootstrap → backfill → validate，
6 轮访谈答案落盘到 `work/interview/` 后没有任何下游脚本消费（Gate 0 ISSUE-011/018）。
由此带来两个缺口：

1. 没有定义访谈答案与 raw 机器抽取候选的优先级；
2. 两者冲突时没有标记规则，raw 候选可能静默覆盖访谈里本人已点头确认的答案。

## Decision

### 1. 三级来源通道（写进每条候选的 `来源通道` 标记）

| 等级 | 通道 | 含义 | 能否作为事实定论 |
|---|---|---|---|
| **A 级 · 访谈** | `work/interview/answers.md` + `round-N.md` 中本人复述确认的答案 | 基准事实 | 可作为本人确认答案；仍需保留原文与出处行 |
| **B 级 · raw 回填** | 从聊天记录机器抽取的候选 | 补证 / 候选归纳 | 只能当候选，不能改写成身份定论 |
| **C 级 · L2 待确认** | 二层回流候选 | 未签字提案 | 只能向本人提问，不得自行补全 |

### 2. 优先级规则（代码实现于 `scripts/interview_source.py` 与 `04_bootstrap_kit.py`）

- 同一槽位（称呼 / 身份 / 主线 / 准则 / 硬规则 / 正反例）先渲染 **A 级访谈**条目；
  **B 级 raw** 条目排在其后，只作补证。
- 访谈条目永远不会被 raw 条目覆盖：即使 raw 池抽不出对应内容，A 级访谈块仍独立成段。
- 每条访谈条目带可追溯出处：`_evidence/interview-lines.md:<行>`（仓内副本）
  + `来源：<answers.md|round-N.md>:<行>`（原始文件与行号）。

### 3. 冲突处理（不允许静默覆盖）

- raw 候选与同槽位访谈答案做弱 token 重叠比对（`raw_agrees`）：
  - 重叠 → 保留为 B 级补证；
  - 不重叠 → 不删除、不替换访谈条目，raw 条目降级并附加：
    `[待确认] 与访谈「<访谈答案>」不一致；以访谈 A 级为准，本条需本人裁定，不得覆盖访谈记录`。
- 冲突条目沿用既有 `[待确认]` tri-state 校验：必须带原文 + 出处，否则 strict 校验失败。
- 比对是保守的：文本太薄、无法判断时按“待核对”处理，不擅自判一致，避免掩盖冲突。

## Consequences

- build 必须显式传入访谈目录/文件才会加载 A 级答案；未传时行为与基线一致（纯 raw 初稿），
  不会假装访谈已被吸收。
- 机器无法判定“本人亲历占比”等主观指标；冲突最终由本人复核裁定，机器只负责把不一致显式摆出来。
- 阈值（A 级条目数下限、各槽位最少条数）留待用户裁定，见 E6-T1 / issue #96。
