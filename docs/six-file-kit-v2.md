# 六份档案设计 v2（薄 AGENTS + 热链接总索引）

> 解决两个问题：`AGENTS.md` 太重、六份内容偏薄。原则是：**AGENTS 只做路由和协议，细节进 `00`~`04`，证据进 `_evidence/`，需要时再按指针取原文。**

## 1. 六份各管什么

| 文件 | 角色 | 该放什么 | 不该放什么 |
|---|---|---|---|
| `AGENTS.md` | 交接路由 / 协作协议 | 站位、四条硬规矩、读法、交付边界 | 详细状态机、长证据、全部个人事实 |
| `00-总入口索引.md` | 热链接地图 | 文件地图、当前主线、七步闭环、命令入口 | 大段个人故事 |
| `01-身份与当前主线.md` | 身份与主线 | 称呼、角色、当前主线、明确放弃项 | 未确认的猜测；`[待确认]` 必须保留 |
| `02-核心判断准则.md` | 判断与取舍 | 道/法/术/器；带原文+出处的准则 | 机器归纳句充数；无出处结论 |
| `03-硬规则与表达黑话.md` | 硬规则/表达 | 持久硬规则、黑话纠偏、边界 | 单次任务指令、对话指责、技术摘录 |
| `04-正反例避坑账.md` | 正例/反例 | 日期+经过+铁律；带原文+出处 | 问句、请求句、AI 总结、材料摘录 |

`_evidence/` 不是第七份档案：它是证据行，只给 `01`~`04` 的引用提供可解析出处。

## 2. 薄 AGENTS 的 28 行结构

已落地：`templates/AGENTS.md`（1,701 bytes / 28 行，补回“动前先思/不盲猜”）。结构是：

1. 一句话读法：先读 `00`，再按索引跳 `01`~`04`。
2. 站位：合伙人、主体是人。
3. 四条硬规矩：原文只读、证据先行、单步最小改动、签字门。
4. 读法：身份→`01`，判断→`02`，规则→`03`，案例→`04`。
5. 交付：先结论后证据；环境结论附命令/退出码；四类人类动作不代做。

旧版 2,345 bytes 保留在 `templates/AGENTS.full.md`，只作对照，不再默认安装。**注意**：本机旧的 `D:\xh-live-demo-20261124\installed\work\kit_afterchat_fixed\AGENTS.md` 仍是 3,920 bytes 的旧协议版；下次 `xh.py init` 或重新 bootstrap 才会换成薄版。没有重装之前，不要声称“本机已经是薄版”。

## 3. 读顺序与热链接

```text
AGENTS.md
  └─ [00-总入口索引](./00-总入口索引.md)   # 唯一总入口
       ├─ 01-身份与当前主线.md             # 我是谁 / 现在做什么 / 放弃什么
       ├─ 02-核心判断准则.md               # 怎么判断 / 怎么取舍
       ├─ 03-硬规则与表达黑话.md            # 不能做什么 / 怎么说人话
       ├─ 04-正反例避坑账.md               # 做过什么 / 踩过什么坑
       └─ _evidence/                       # 只在需要原文时按行号取
```

规则：**默认只读 `AGENTS` + `00`**；只有问题落到具体槽位时才读对应文件。这样上下文不会被六份全文灌满。

## 4. 证据等级与签字门

| 等级 | 来源 | 用法 |
|---|---|---|
| A · 访谈/原话 | 本人访谈或带原文+出处的原话 | 可作基准；冲突时以本人签字为准 |
| B · raw 回填 | 多条原话归纳 | 只能写“候选归纳”，不能写“用户就是” |
| C · L2 待确认 | 二层回流候选 | 只能提问/复核；未经本人签字不得转正 |

硬门：`[待确认]` 是唯一合法初始状态；`review --confirm` + 本人签字后才能进正式正文。AI 代做/转述/材料必须标出，不能冒充“本人亲历”。

## 5. L2 信号 → 档案位置

| 信号 | 目标 | 锚点 |
|---|---|---|
| 反复错误/踩坑 | `04` | `## 二、反例标本` |
| 正向复现 | `04` | `## 一、正例标本` |
| 抱怨/卡点 | `02` | `## 三、术` / `## 四、器` |
| 核心事实 | `01` | `## 一、不可篡改的核心事实` |
| 新硬规则/黑话 | `03` | `## 一` / `## 三` |
| 索引/流程 | `00` | `## 二、七步闭环流程` |
| `AGENTS.md` | 只读 | 规矩变更由本人手动改 |

每个可写档案末尾必须有显式锚点 `[XH-L2-PENDING-END]`；`08_l2_apply.py` 只在这个锚点前插入“二层回流待确认区”。缺锚点会安全失败（退出码 2），不会盲追加到文件尾；已有待确认区不会被追加第二份。

## 6. 机器可判标准

`docs/scorecard.md` 默认：`coverage≥0.80`、`answerable≥0.67`、`citation≥0.90`、`mainline_unique=1`。  
结构 `VALIDATE_OK` ≠ 可交付；还要 `review --confirm` + 独立 Agent 盲测。当前本机旧 kit 的真实数值是 `coverage=0.83`、`answerable=0.67`、`citation=1.00`、`mainline_unique=0.00`（3 条主线候选，评分卡 FAIL），`review=pending_review`、`VERIFY_BLOCKED_REVIEW`，且 `01` 身份仍是 `[待确认][RAW_ZERO_HIT]`。
