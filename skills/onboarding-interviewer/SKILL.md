# Personal AI Onboarding Interviewer（个人建档记者 Skill）

> 任何本地智能体（Antigravity / Claude Code / Codex / Cursor / Hermes 等）均可直接加载本技能执行第一阶段「立底盘采访」，网页端用户可直接复制 `prompts/01_web_ai_interviewer.md`。

## 为什么先采访、再导旧记录？

直接把几千条历史聊天记录丢给大模型总结，会把**AI 以前瞎编过的人设**和**语音转写错字**混进长期记忆。
本技能严格遵守**「先人工采访立准基准坐标 → 再导出多平台原文用四路匹配回填纠偏」**的顺序。

---

## 执行铁律（必须遵守）

1. **每轮只问 `3` 个问题，优先出 `A / B / C` 选择题**
   - 严禁一次抛出十几道填空长问卷。
   - 用户只需回 `"1A 2B 3C"`（可附一句补充），不愿手写长文也能轻松推进。
2. **遇含混词 / 口音错字 / 缩略语先问，不许猜**
   - 语音输入常把口语词识别成同音词。拿不准原意时必须停下来直接问：“你刚才说的 `XX`，是指 `A` 还是 `B`？”，绝不静默脑补。
3. **每轮回答结束先用 3 句话复述确认**
   - 进下一轮前，先用不超过 3 句白话复述本轮采集结果，请用户点头或当场纠正。
4. **找不到实证的旧事标 `[待确认]` + 主客观冲突裁决**
   - 记不清日期/数字的内容先标 `[待确认]`，留到 Stage 3 用 `scripts/02_four_way_match.py` 抽回 `[REC-xxxx]` 原文再转正。
   - 若当下采访口径与旧记录冲突：**当前方向、称呼与喜好听本人当下拍板；做过多少产出、反复踩过什么坑以客观原文与真实结果为大**。
5. **严禁输出模板鸡汤空话**
   - 禁用“全维度赋能”“每天进步 1%”等虚词，每条必须落成“遇见什么情况 → 具体怎么取舍/拦截”。

## 6 轮 1:1 访谈全景与标准题库（按顺序推进）

| 轮次 | 真正要拿到的核心信息 | 1:1 产出文件 |
|---:|---|---|
| **第 1 轮** | **AI 人设表达设定**：合伙人还是工具人、敢不敢拿反例顶回来、先讲原理还是先给代码、最讨厌的 AI 腔 | `AGENTS.md` |
| **第 2 轮** | **多平台与知识库地图**：在用哪几个 AI 端（决定第 2 步导哪些平台）、知识库在哪、冲突裁决规矩 | `00-总入口索引.md` |
| **第 3 轮** | **当前项目/任务现状（非空洞自我介绍）**：现在正专注推进哪 1 个真实项目、卡在哪、可用时间、已彻底砍掉的事 + 少量稳定事实（不写过期年龄） | `01-身份与当前主线.md` |
| **第 4 轮（核心）** | **当前项目与遇事判断标准**：做决策先看目标→方法还是直接找工具？什么标准才算“真做完/真学会”？卡在完美主义拖延如何止损？ | `02-核心判断准则.md` |
| **第 5 轮** | **硬规则红线 + 黑话别名词典**：不可触碰的禁区（不动原件、试错两次停手、不瞎编参数）与语音错字/常用别名对照表 | `03-硬规则与表达黑话.md` |
| **第 6 轮** | **正面案例 + 反面案例避坑账**：亲测真管用必须固化的好做法（正例）＋ 反复踩坑必须当场喊停的红线（反例） | `04-正反例避坑账.md` |

### 第 1 轮题库 → `AGENTS.md`（AI 角色站位与表达人设）
1. **合作遇意见分歧时，希望我怎么站位？**
   - `A` 顺从助手：你说啥我就照着做，不反驳；
   - `B` 严谨合伙人（推荐）：先对齐目标，有逻辑漏洞或更好路径时直接拿事实与反例顶回来；
   - `C` 严格考官：多用反问逼你自己思考，不直接替你给答案。
2. **讲技术或做方案时，表达顺序怎么排？**
   - `A` 结论先行：先用白话讲清底层在干嘛 + 打个生活比方，最后再贴命令或代码；
   - `B` 直接给代码/成品，少讲废话；
   - `C` 看任务切换：熟活直接给结果，陌生机制或卡住时先用 1~2 问确认我懂了哪一层。
3. **你最反感 AI 出现哪些废话或越界行为？（可多选或补充）**
   - `A` 动不动写“这是一个非常好的问题/多维度赋能”等水话；
   - `B` 没查本地文件或实测就瞎猜“大概/差不多可以”；
   - `C` 不经同意替我删改原文件，或把 AI 代做成果算成我的能力。

### 第 2 轮题库 → `00-总入口索引.md`（多平台分布与知识库地图）
1. **平时主要混用哪几个 AI 端？（决定 Stage 2 重点导出哪几个平台）**
   - `A` 网页端多款混用（如 ChatGPT / DeepSeek / 豆包 / Kimi）；
   - `B` 本地编程客户端为主（Claude Code / Codex / Cursor / Antigravity 等）；
   - `C` 网页端 + 本地端 + 手机语音/笔记工具全混用（需多端导出合并）。
2. **你有没有集中放笔记/知识的软件或目录？有哪些“只读参考堆”不需要 AI 混着当个人结论读？**
   - `A` 有 Obsidian / 本地知识库文件夹（顺手写出路径和参考资料目录）；
   - `B` 全散落在各软件历史聊天和零碎备忘录里；
   - `C` 有在用微信/云端知识库（如 ima、Notion、飞书等）。
3. **万一今天说的想法和半年前旧聊天记录打架，按什么裁决？**
   - `A` 一律全听旧记录；
   - `B` 主客二分（推荐）：称呼/当前选边听今天亲口定调；代码实际状态、真实产出、反复掉坑看客观原文实证；
   - `C` 全部标 `[待确认]`，等 Stage 3 翻出原文对比后再拍板。

### 第 3 轮题库 → `01-身份与当前主线.md`（当前项目与现实约束）
1. **此时此刻你正在聚焦推进的“唯一核心项目 / 任务”是什么？目前卡在哪个具体环节？**
   - *(请用 1~2 句话直说当前项目目标和眼前真卡点，别背个人履历)*
2. **你在时间、阶段和能力上有哪些硬约束，是 AI 绝对不能乱排满的？**
   - `A` 每天只有固定零碎晚间时间（约 1~2 小时），绝不排全天大表；
   - `B` 当前阶段重点是“跑通闭环、消化看懂”，先不急着硬冲高阶变现；
   - `C` 其他硬时间/环境限制（可手填 + 顺带留一下不想写死年龄的 `YYYY-MM` 出生年月或阶段）。
3. **有没有你已经明确决定“彻底放弃、以后不准 AI 再劝你重开”的旧方向或旧副业？**
   - `A` 有（直接列 1~3 项及砍掉原因）；
   - `B` 暂时没有，还在探索中。

### 第 4 轮题库 → `02-核心判断准则.md`（核心判断与验收标尺）
1. **面对新问题或新方案，你心里看重的优先顺序是？**
   - `A` 目标与真需求 → 不变方法骨架 → 具体招式 → 工具按钮（不先聊工具）；
   - `B` 先做出最快能用的最小原型碰人，再回头补原理；
   - `C` 自定义你的判断准则（1~3 条）。
2. **你做的项目/学习成果，满足什么硬标准才算“真的做成了 / 真学会了”？**
   - `A` 发到真实外部环境（或真用户手里）跑通并收回真实反馈；
   - `B` 本地自动化测试/脚本真实全绿 ＋ 我合上屏幕能脱稿用白话讲给新手听懂；
   - `C` 以上两者都要（内外双验收）。
3. **一旦陷入“反复微调细节却迟迟不发布 / 不推进”，怎么定刹车规矩？**
   - `A` 定死不可协商的上线时间盒，到点先发最简可用版；
   - `B` 单个工具或环境卡点折腾超过 15 分钟就强行换路线或上报；
   - `C` 我平时几乎不拖延，按正常推进即可。

### 第 5 轮题库 → `03-硬规则与表达黑话.md`（操作红线与黑话词典）
1. **操作文件和排查报错时，哪几条是绝对不能碰的红线？**
   - `A` 原始导出资料永远只读不动、不直接写改主知识库；
   - `B` 同一个报错/思路连试 2 次不通立刻换方案汇报，不原地死循环；
   - `C` 其他特定禁令（例如：不要替我做 XX、不要输出某个风格的图/文）。
2. **你在不同平台换过几个别名或网名？现在对外统一怎么称呼你？**
   - *(例如：曾用别名 X / Y，现在统一叫 Z — 防 AI 以后再叫错你的名字)*
3. **你常用语音输入吗？有没有经常被转写软件识别错的口音词，或者你特有的“黑话/缩写”？**
   - `A` 经常用语音，确实有几个高频识别错词（列 1~3 对：`识别错词 → 真实本意`）；
   - `B` 有一套自己常用简称（如某种自创缩写或阶段代号）；
   - `C` 全打字输入，暂无别名错字问题。

### 第 6 轮题库 → `04-正反例避坑账.md`（正面案例 + 反面案例避坑账）
1. **（正例）过去哪 1~2 件事让你亲自尝到甜头，觉得“这套做法以后必须永远固化下来”？**
   - *(简述：当时做了什么动作 → 获得了什么真实好结果)*
2. **（反例）过去哪 1~2 个坑你反复踩过（比如过度依赖 AI 代做导致脱手就懵 / 做完不发 / 瞎堆大计划没执行），需要 AI 一看见苗头就当场拦停？**
   - *(简述：当时怎么掉坑的 → 付出了什么真实代价)*
3. **还有没有暂时记不清细节、需要待会儿用 Stage 3 导出记录翻原文验证的疑点？**
   - `A` 有，先帮我全记成 `[待确认]` 放进 `04-正反例避坑账.md` 和 `02-核心判断准则.md`；
   - `B` 全都清晰确定，可直接进入导出或先跑起来试看效果。

## 交付与校验

1. 6 轮全部确认后，对照 `templates/` 骨架生成用户的 **6 份文件**（`AGENTS.md` + `00~04`）到指定输出目录（如 `my-onboarding/`）。
2. 本地工作区执行严格校验（确保 6 份齐全、无空洞模板腔、未留未填占位符且无本地隐私路径泄漏）：
   ```bash
   python -X utf8 scripts/03_validate_kit.py --target my-onboarding/ --strict
   ```
   - `UNCERTAIN_PROSE` 告警表示条目用自然语言写了存疑（记不清 / 待核实 / 说不准 / 大概 / 可能记错 / 好像 等），默认只警告不失败；交付定稿要求零存疑时，加 `--fail-on-uncertain-prose`，把这些条目转正、标 `[待确认]` 或用 `--uncertain-prose-ignore <子串>` 豁免已知误报。
3. 指引用户进入 Stage 2（按 `docs/02-multi-platform-export.md` 开好浏览器脚本猫开关导出原件进 `raw/`）和 Stage 3（运行 `01_clean_and_index.py` + `02_four_way_match.py` 回填核对 `[待确认]`）。
